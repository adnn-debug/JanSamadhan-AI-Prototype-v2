IMPORTANT TRUTH FOR THE JURY
The prototype uses LLM-assisted decision support when Groq is configured and deterministic local fallback when it is unavailable.
The core automatic duplicate merge is still based on explainable text/concept, locality and category similarity. GIS adds separate nearby-case and coordinate-based recurrence signals where citizens provide a map pin.
AI and GIS signals are advisory. Government / Nodal Administrator remains the case owner and human validation controls routing and completion.
Do not claim the current prototype is a trained proprietary model, vector-search system or production-ready government platform.

POSTGRESQL MIGRATION ARCHITECTURE
- PostgreSQL is the primary cloud persistence layer.
- Flask exposes controlled API endpoints for accounts, challenges, seeding and daily complaint limits.
- Important challenge fields (category, priority, stage, district, location, institution) are first-class relational columns for filtering/indexing.
- Nested prototype state (history, proposals, partner offers, AI/GIS metadata, impact records) is retained in JSONB so the working demo does not lose functionality during migration.
- citizen_daily_limits uses a PostgreSQL atomic upsert so the 10-reports-per-day rule is enforced consistently across devices.
- Browser localStorage remains only as a resilience/demo fallback, not the primary cloud database.
- A later production normalization can split history, proposals, milestones and partner offers into dedicated relational tables without changing the public workflow.
